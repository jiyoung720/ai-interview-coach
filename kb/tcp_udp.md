# TCP와 UDP

TCP는 연결을 맺고 데이터를 주고받는 프로토콜이다. 통신 전에 3-way handshake로 연결을 수립하는데, 클라이언트가 SYN을 보내고 서버가 SYN-ACK로 답하고 클라이언트가 다시 ACK를 보내는 세 번의 왕복이다. 이 과정에서 양쪽이 서로 데이터를 받을 준비가 됐음을 확인한다.

TCP는 전달을 보장한다. 보낸 데이터에 순서 번호를 붙이고 상대가 받았다는 응답을 확인하며, 응답이 오지 않으면 다시 보낸다. 순서가 뒤바뀌어 도착해도 번호를 보고 원래 순서로 재조립한다. 애플리케이션은 이런 처리가 일어나는지 모른 채 온전한 데이터만 받는다.

UDP는 연결을 맺지 않고 그냥 보낸다. 도착 확인도, 재전송도, 순서 보장도 하지 않는다. 대신 handshake와 확인 응답에 드는 시간이 없어 빠르고, 헤더도 작다. 실시간 영상이나 음성 통화처럼 조금 유실되더라도 계속 흘러가는 것이 중요한 경우에 적합하다. 이미 지나간 음성을 재전송받아 봐야 쓸모가 없기 때문이다.

선택 기준은 "빠뜨리면 안 되는가"와 "늦으면 안 되는가" 중 무엇이 중요한지다. 웹 요청이나 파일 전송은 데이터가 하나라도 빠지면 안 되므로 TCP를 쓰고, 실시간 스트리밍은 지연이 치명적이므로 UDP를 쓴다. 다만 TCP의 신뢰성 보장은 공짜가 아니어서, 재전송이 일어나는 동안 뒤 데이터까지 함께 지연되는 현상이 생길 수 있다.
