# N+1 문제와 조인 전략

N+1 문제는 목록을 조회한 뒤 각 항목의 연관 데이터를 개별 쿼리로 가져오면서 쿼리가 폭증하는 현상이다. 게시글 10건을 조회하는 쿼리 1번을 날린 뒤, 각 게시글의 작성자를 가져오려고 10번의 추가 쿼리가 나가면 총 11번이 실행된다. 목록이 100건이면 101번이 된다. 코드에서는 반복문 안에서 연관 객체에 접근하는 한 줄로 보이지만, 실제로는 데이터 건수만큼 데이터베이스 왕복이 일어난다.

원인은 지연 로딩(Lazy Loading)이다. ORM은 연관 데이터를 실제로 사용하는 시점까지 조회를 미루는데, 반복문 안에서 접근하면 그 시점이 매 항목마다 찾아온다. 지연 로딩 자체는 필요 없는 데이터를 안 읽는다는 점에서 합리적인 기본값이지만, 목록 조회와 만나면 문제가 된다.

해결의 기본은 한 번의 쿼리로 연관 데이터를 함께 가져오는 것이다. 조인을 사용해 필요한 데이터를 한 번에 조회하거나, 연관 데이터를 IN 절로 묶어 한 번 더 조회하는 방식을 쓴다. 전자는 왕복이 1회로 끝나지만 조인 결과가 커질 수 있고, 후자는 왕복이 2회지만 각 쿼리가 단순하다.

주의할 점은 무조건 즉시 로딩으로 바꾸는 것이 답은 아니라는 것이다. 항상 함께 읽는다면 즉시 로딩이 맞지만, 대부분의 경우 쓰지 않는 연관 데이터까지 매번 읽으면 오히려 낭비다. 그래서 지연 로딩을 기본으로 두고 목록 조회처럼 N+1이 발생하는 지점에서만 명시적으로 함께 조회하는 방식이 권장된다. 실제로 몇 번의 쿼리가 나가는지는 쿼리 로그를 켜서 눈으로 확인하는 것이 확실하다.
