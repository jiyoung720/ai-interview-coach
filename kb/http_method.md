# HTTP 메서드

HTTP 메서드는 클라이언트가 서버에 요청하는 작업의 종류를 나타낸다. GET은 리소스 조회, POST는 리소스 생성, PUT은 리소스 전체 교체, PATCH는 리소스 일부 수정, DELETE는 리소스 삭제에 사용된다. 같은 URI라도 어떤 메서드로 요청하느냐에 따라 서버가 수행하는 동작이 달라진다.

GET은 조회 전용이므로 요청 본문을 쓰지 않고 필요한 값은 URL 쿼리 파라미터로 전달한다. 그래서 파라미터가 주소창과 서버 로그에 그대로 남아 민감한 정보를 담으면 안 된다. POST는 본문에 데이터를 담아 보내므로 길이 제한이 사실상 없고 주소에 노출되지도 않는다.

PUT과 PATCH는 둘 다 수정이지만 범위가 다르다. PUT은 리소스 전체를 요청 본문의 내용으로 교체하므로, 보내지 않은 필드는 비워지거나 기본값이 된다. PATCH는 보낸 필드만 부분적으로 고친다. 사용자 정보 중 이메일만 바꾸고 싶다면 PATCH가 적합하고, 전체를 새 값으로 덮어쓸 때는 PUT이 맞다.

메서드 선택은 관례가 아니라 계약에 가깝다. 브라우저나 프록시, 캐시 서버가 메서드의 의미를 전제로 동작하기 때문이다. 예를 들어 GET 응답은 캐시될 수 있고 재시도될 수 있는데, 조회가 아닌 작업을 GET으로 만들면 의도치 않게 여러 번 실행될 수 있다. 관련해서 같은 요청을 반복해도 결과가 같은지를 다루는 개념이 멱등성이다.
