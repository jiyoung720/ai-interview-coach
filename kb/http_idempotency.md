# 멱등성 (Idempotency): 같은 요청을 여러 번 보내도 결과가 같은 성질

멱등성 또는 Idempotency는 같은 요청을 여러 번 보내도 결과가 동일한 성질을 말한다. 요청을 한 번 보내든 열 번 반복해서 보내든 서버의 최종 상태가 같으면 그 요청은 멱등하다고 한다. 멱등하다는 것은 반복 실행이 안전하다는 뜻이며, HTTP 메서드 중 GET, PUT, DELETE는 멱등하고 POST는 멱등하지 않다.

메서드별로 나눠 보면 이유가 분명해진다. GET은 조회만 하므로 상태를 바꾸지 않는다. PUT은 리소스 전체를 주어진 값으로 교체하므로 몇 번을 보내도 최종 상태가 같다. DELETE는 첫 요청에서 삭제하고 이후 요청은 이미 없는 상태를 유지하므로 결과가 동일하다. 반면 POST는 매 요청마다 새 리소스를 만들기 때문에 두 번 보내면 두 개가 생긴다. PATCH는 경우에 따라 갈리는데, 값을 특정 값으로 지정하면 멱등하지만 "수량을 1 늘려라" 같은 상대적 변경이면 멱등하지 않다.

멱등성이 실무에서 중요한 이유는 재시도 때문이다. 네트워크 오류로 응답을 받지 못했을 때 요청이 서버에 도달했는지 알 수 없다. 이때 멱등한 요청이면 그냥 다시 보내도 안전하지만, 멱등하지 않은 요청은 재시도가 곧 중복 실행이 된다. 주문이 두 번 들어가거나 결제가 두 번 일어나는 사고가 여기서 나온다.

그래서 결제나 주문처럼 중복이 치명적인 POST 요청에는 멱등성 키(Idempotency Key)를 함께 보낸다. 클라이언트가 요청마다 고유한 키를 생성해 헤더에 담으면, 서버는 그 키를 저장해두고 같은 키로 다시 들어온 요청은 처음 결과를 그대로 돌려준다. 이렇게 하면 멱등하지 않은 메서드에도 멱등성을 부여할 수 있다.

멱등성과 안전성(Safety)은 다른 개념이다. 안전한 메서드는 서버 상태를 아예 바꾸지 않는 것으로 GET이 여기 해당한다. DELETE는 멱등하지만 상태를 바꾸므로 안전하지는 않다. 안전한 메서드는 모두 멱등하지만 그 반대는 성립하지 않는다.
