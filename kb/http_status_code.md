# HTTP 상태 코드

HTTP 상태 코드는 응답의 결과를 세 자리 숫자로 나타낸다. 첫 자리가 분류를 뜻해서 2xx는 성공, 3xx는 리다이렉션, 4xx는 클라이언트 오류, 5xx는 서버 오류를 의미한다. 이 구분이 중요한 이유는 4xx와 5xx가 책임의 소재를 가르기 때문이다. 4xx는 요청을 보낸 쪽이 잘못한 것이고, 5xx는 서버가 처리하다 실패한 것이다.

자주 쓰이는 2xx는 200 OK와 201 Created다. 201은 리소스를 새로 만들었을 때 쓰며, 보통 생성된 리소스의 위치를 Location 헤더에 담아 함께 알려준다. 요청은 받았지만 처리가 끝나지 않았다면 202 Accepted를 쓴다.

401 Unauthorized와 403 Forbidden은 자주 혼동된다. 401은 인증이 되지 않은 상태로, "당신이 누구인지 모르겠다"는 뜻이다. 토큰이 없거나 만료됐을 때 반환한다. 403은 인증은 됐지만 권한이 없는 상태로, "당신이 누구인지는 알지만 이 작업은 허용되지 않는다"는 뜻이다. 일반 사용자가 관리자 기능에 접근할 때가 여기 해당한다. 이름과 달리 401이 인증(Authentication), 403이 인가(Authorization)에 대응한다.

400 Bad Request는 요청 형식 자체가 잘못된 경우이고, 404 Not Found는 리소스가 없는 경우다. 422 Unprocessable Entity는 형식은 맞지만 내용이 처리할 수 없는 경우에 쓴다. 500 Internal Server Error는 서버 내부 오류를 뭉뚱그린 코드라, 원인을 구분할 수 있다면 502 Bad Gateway나 503 Service Unavailable처럼 더 구체적인 코드를 쓰는 편이 낫다.
