# REST API 설계

REST(Representational State Transfer)는 자원을 URI로 표현하고 행위를 HTTP 메서드로 표현하는 아키텍처 스타일이다. `/users/1`이라는 URI에 GET을 보내면 조회, DELETE를 보내면 삭제로 해석된다. URI에는 자원만 담고 동작은 메서드가 나타내므로, `/getUser`나 `/deleteUser` 같이 URI에 동사를 넣는 것은 REST 원칙에 어긋난다.

자원 이름은 복수형 명사를 쓰는 것이 관례다. `/users`는 사용자 목록, `/users/1`은 특정 사용자를 가리킨다. 계층 관계는 경로로 표현해서 `/users/1/orders`는 1번 사용자의 주문 목록이 된다. 다만 계층이 깊어지면 URI가 길고 복잡해지므로 보통 두 단계 정도까지만 중첩한다.

조회 조건은 URI 경로가 아니라 쿼리 파라미터로 넘긴다. `/users?status=active&page=2`처럼 필터링, 정렬, 페이지네이션을 표현한다. 경로는 "무엇을"에 해당하고 쿼리는 "어떻게 걸러서"에 해당한다고 보면 구분이 쉽다.

REST의 무상태성(Stateless)은 서버가 요청 사이의 상태를 기억하지 않는다는 원칙이다. 각 요청은 처리에 필요한 정보를 스스로 다 담고 있어야 하므로 인증 정보도 매 요청에 함께 보낸다. 서버가 상태를 갖지 않으면 어느 서버가 요청을 받아도 같은 결과가 나오므로 수평 확장이 쉬워진다.
