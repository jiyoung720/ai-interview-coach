# 실행 계획과 쿼리 튜닝

실행 계획(Execution Plan)은 데이터베이스가 쿼리를 어떤 순서와 방법으로 처리할지 정한 결과다. 같은 결과를 내는 쿼리라도 어떤 인덱스를 쓰는지, 테이블을 어떤 순서로 조인하는지에 따라 속도가 크게 달라진다. PostgreSQL에서는 `EXPLAIN`으로 계획을 보고, `EXPLAIN ANALYZE`로 실제 실행까지 해서 걸린 시간을 확인한다.

계획에서 가장 먼저 보는 것은 스캔 방식이다. Seq Scan은 테이블 전체를 순차적으로 읽는 방식이고, Index Scan은 인덱스를 타고 필요한 행만 찾는 방식이다. 조건에 맞는 행이 전체의 극히 일부인데 Seq Scan이 나온다면 인덱스가 없거나 있어도 사용되지 않는 상태를 의심해야 한다.

인덱스가 있는데도 안 타는 경우가 있다. 인덱스 컬럼에 함수를 씌우거나 연산을 하면 정렬된 순서를 이용할 수 없어 인덱스를 못 쓴다. 컬럼의 값 종류가 적어 조건에 맞는 행이 테이블의 상당 부분을 차지할 때도, 옵티마이저가 인덱스를 타는 것보다 전체를 읽는 편이 빠르다고 판단해 일부러 Seq Scan을 고르기도 한다.

`EXPLAIN ANALYZE`에서는 예상 행 수와 실제 행 수를 비교하는 것이 중요하다. 둘이 크게 차이 나면 통계 정보가 낡아 옵티마이저가 잘못된 판단을 하고 있을 가능성이 있다. 튜닝은 추측이 아니라 계획을 확인하고, 바꾼 뒤 다시 계획을 확인하는 방식으로 진행해야 한다. 인덱스를 추가했다고 해서 실제로 사용된다는 보장은 없기 때문이다.
